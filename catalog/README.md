# Каталог кабинетов (локальный, в git не попадает)

Здесь лежит `cabinet-presets.json` — стартовый каталог LED-кабинетов,
который приложение подставляет в базу при первом запуске и возвращает
кнопкой «Вернуть стандартные» в настройках.

Каталог намеренно **не хранится в репозитории**: он содержит данные наших
моделей (габариты, вес, потребление), а не код. Каталог целиком лежит в
`.gitignore`, поэтому в GitHub он не уходит.

## Формат

```json
{
  "format": "dl-screen-cabinet-catalog",
  "version": 1,
  "presets": [
    {
      "id": "brand-model-pitch",
      "brand": "Бренд",
      "model": "Модель",
      "widthMm": 500,
      "heightMm": 500,
      "pixelPitchMm": 2.5,
      "resolutionX": 200,
      "resolutionY": 200,
      "weightKg": 7.6,
      "maxPowerW": 145,
      "avgPowerW": 48
    }
  ]
}
```

- `id` — уникальный идентификатор пресета (латиница, цифры, дефисы).
- Габариты — миллиметры, разрешение — пиксели на кабинет, мощность — Вт на
  кабинет (не на м²), вес — кг.
- Допустимые диапазоны значений и обязательность полей проверяются
  `validatePreset` из `src/shared/presetValidation.ts`; пресет, который не
  проходит проверку, пропускается с предупреждением в консоли, остальные
  остаются.
- Необязательный ключ `sources` (объект `id → строка`) ни на что не влияет:
  в нём удобно хранить ссылки на спек-листы, откуда взяты цифры.

## Как приложение его находит

1. `$DL_CABINET_CATALOG` — явный путь к JSON (удобно для проверок и CI).
2. `<корень приложения>/catalog/cabinet-presets.json` — то есть этот файл
   в режиме разработки и он же внутри установленного приложения, если
   попал в сборку.

Если файла нет, приложение запускается с пустой библиотекой (экран
предложит добавить кабинет в настройках), а кнопка «Вернуть стандартные»
сообщит, что каталог не найден.

Каталог остаётся локальным: он не попадает ни в git (шаблон `catalog/*.json`
в `.gitignore`), ни в установочные пакеты — `build.files` в `package.json`
включает только `dist/**/*` и `package.json`. Поэтому релиз выходит с пустой
базой кабинетов: пользователь заводит кабинеты сам или импортом, а каталог
из этого файла подставляется только при локальном запуске из исходников
(удобно для разработки и проверок).
